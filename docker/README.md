# Docker Setup for MiniRAG Application

This directory contains the Docker setup for the MiniRAG application, including all necessary services for development and monitoring.

## Services

- **FastAPI Application**: Main application running on Uvicorn
- **Nginx**: Web server for serving the FastAPI application
- **PostgreSQL (pgvector)**: Vector-enabled database for storing embeddings
- **Postgres-Exporter**: Exports PostgreSQL metrics for Prometheus
- **Prometheus**: Metrics collection
- **Grafana**: Visualization dashboard for metrics
- **Node-Exporter**: System metrics collection

## Setup Instructions

### 1. Set up environment files

From the repository root, create the files referenced by `docker-compose.yml`:

```bash
cp docker/envv/.env.example.app docker/envv/.env.app
cp docker/envv/.env.example.postgres docker/envv/.env.app.postgres
cp docker/envv/.env.example.postgresexporter docker/envv/.env.app.postgresexporter
cp docker/envv/.env.example.grafana docker/envv/.env.app.grafana
cp docker/minirag/alembic.example.ini docker/minirag/alembic.ini
```

Edit the database credentials so they match in the app, PostgreSQL, exporter, and Alembic files. Set the LLM provider keys and Grafana admin password as well. See [Configuration](../docs/Configuration.md).

### 2. Start the services

```bash
cd docker
docker compose up --build -d
```

To start only specific services:

```bash
docker compose up -d fastapi nginx pgvector
```

If you encounter connection issues, you may want to start the database services first and let them initialize before starting the application:

```bash
# Start databases first
docker compose up -d pgvector postgres-exporter
# Wait for databases to be healthy
sleep 30
# Start the application services
docker compose up fastapi nginx prometheus grafana node-exporter --build -d
```

To remove this Compose project's containers and persistent data (irreversible):

```bash
docker compose down --volumes --remove-orphans
```

### 3. Access the services

- FastAPI Application: http://localhost:8000
- FastAPI Documentation: http://localhost:8000/docs
- Nginx (serving FastAPI): http://localhost
- Prometheus: http://localhost:9090
- Grafana: http://localhost:3000

## Volume Management

### Managing Docker Volumes

Docker volumes are used to persist data generated by and used by Docker containers. Here are some commands to manage your volumes:

1. **List all volumes**:
   ```bash
   docker volume ls
   ```
2. **Inspect a volume**:
   ```bash
   docker volume inspect <volume_name>
   ```

   - list files in a volume:
   ```bash
   docker run --rm -v <volume_name>:/data busybox ls -l /data
   ```

3. **Remove a volume**:
   ```bash
   docker volume rm <volume_name>
   ```
4. **Backup volume for migration**:
   ```bash
    docker run --rm -v <volume_name>:/volume -v $(pwd):/backup alpine tar cvf /backup/backup.tar /volume
    ```

5. **Restore volume from backup**:
   ```bash
    docker run --rm -v <volume_name>:/volume -v $(pwd):/backup alpine sh -c "cd /volume && tar xvf /backup/backup.tar --strip 1"
    ```

Do not run host-wide volume-pruning or volume-removal commands to reset this project. `docker compose down --volumes` removes this project's named volumes and permanently deletes its database, uploads, and monitoring data. For PostgreSQL backups, prefer `pg_dump` and `pg_restore`.

## Monitoring

### FastAPI Metrics

FastAPI is configured to expose Prometheus metrics at the `/metrics` endpoint. These metrics include:

- Request counts
- Request latencies
- Status codes

Prometheus is configured to scrape these metrics automatically.

### Visualizing Metrics in Grafana

1. Log into Grafana at http://localhost:3000 using the admin credentials in `docker/envv/.env.app.grafana`.
2. Add Prometheus as a data source (URL: http://prometheus:9090)
3. Import dashboards for FastAPI, and PostgreSQL

## Development workflow

The Docker Compose service does not mount the source tree, so source edits do not hot-reload in the container. See [Development](../docs/Development.md) for running the API locally with reload enabled.

## Troubleshooting

### Connection Errors

If you see connection errors when starting the services:

1. **Database Connection Refused**: This often happens when the FastAPI app tries to connect to databases before they're ready.
   ```
   Connection refused: [Errno 111] Connection refused
   ```
   
   Solutions:
   - Start database services first, wait, then start the application
   - Check database logs: `docker compose logs pgvector`
   - Ensure your database credentials in `.env.app` match those in `.env.app.postgres`

2. **Restart the FastAPI service** after databases are running:
   ```bash
   docker compose restart fastapi
   ```

3. **Check service status**:
   ```bash
   docker compose ps
   ```

4. **View logs** for more details:
   ```bash
   docker compose logs --tail=100 fastapi
   docker compose logs --tail=100 pgvector
   ```
